# Terraform Apply

## Overview

This section introduces the **`terraform apply`** command, which executes the infrastructure changes generated by Terraform. After reviewing the execution plan, Terraform applies the approved changes and updates the infrastructure to match the desired state.

It helps build an understanding of how Terraform provisions and manages infrastructure, making it essential for **Infrastructure as Code**, **cloud automation**, **change management**, and modern DevOps workflows.

---

## Terraform Apply

**`terraform apply`**  
A command that executes the Terraform execution plan and applies the approved infrastructure changes.

### Role in Terraform

- Applies infrastructure changes
- Creates, modifies, and destroys resources
- Prompts for deployment confirmation
- Updates the Terraform state file
- Brings infrastructure to the desired state

`terraform apply` takes the execution plan generated by Terraform and performs the required infrastructure changes. Once approved, Terraform creates, updates, or removes resources and records the new infrastructure state.

---

## Execution Plan

**Execution Plan**  
A preview of the infrastructure changes Terraform intends to make before applying them.

### Role in Terraform Apply

- Reviews planned infrastructure changes
- Displays resources to be created, modified, or destroyed
- Helps validate deployments before execution
- Reduces the risk of unintended changes
- Requires user confirmation before deployment

Before making any changes, Terraform generates an execution plan similar to `terraform plan`. This allows the proposed changes to be reviewed before they are applied.

---

## State File Update

**State File Update**  
The process of recording the latest infrastructure after Terraform successfully applies the deployment.

### Role in Terraform

- Records the latest infrastructure state
- Tracks newly created resources
- Updates modified resource information
- Removes deleted resources
- Maintains idempotent deployments

After the deployment completes successfully, Terraform updates the state file to reflect the current infrastructure. This enables future Terraform commands to accurately compare the current state with the desired state.

### Execution Plan

Terraform first generates an execution plan showing the infrastructure changes that will be performed.

The output displays:

- Resources to be created (`+`)
- Resources to be updated (`~`)
- Resources to be destroyed (`-`)

This allows the proposed deployment to be reviewed before any infrastructure changes are made.

---

### Deployment Confirmation

```text
Do you want to perform these actions?

Only 'yes' will be accepted to approve.
```

Before applying any changes, Terraform asks for confirmation. Entering **`yes`** approves the deployment and allows Terraform to begin provisioning the infrastructure.

---

### Applying Changes

After approval, Terraform performs each action defined in the execution plan.

During this stage, Terraform creates new resources, modifies existing resources, removes resources marked for deletion, and updates the infrastructure until it matches the desired state.

---

### Updating the State File

Once all actions have completed successfully, Terraform updates the **`terraform.tfstate`** file to record the latest infrastructure. This ensures future Terraform operations accurately reflect the current state of the environment.

> [!IMPORTANT]
> Always review the execution plan before approving **`terraform apply`**. Once confirmed, Terraform will make real changes to your infrastructure, including creating, modifying, or deleting cloud resources.

---

## Key Takeaways

- `terraform apply` executes the Terraform execution plan
- Terraform requests confirmation before making infrastructure changes
- Resources can be created, modified, or destroyed during deployment
- The Terraform state file is updated after a successful deployment
- Always review the execution plan before approving infrastructure changes
