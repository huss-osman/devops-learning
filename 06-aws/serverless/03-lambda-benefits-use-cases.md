## Benefits of AWS Lambda

AWS Lambda provides several advantages for building modern serverless applications.

Benefits include:

* Pay-per-use pricing
* Automatic scaling
* No server management
* High availability
* Tight integration with AWS services
* Support for multiple programming languages

Unlike traditional servers, Lambda only charges for the time your code is executing.

AWS Free Tier includes:

* 1 million free requests per month
* 400,000 GB-seconds of compute time per month

Lambda integrates seamlessly with services such as:

* Amazon S3
* Amazon DynamoDB
* Amazon API Gateway
* Amazon SNS
* Amazon SQS
* Amazon EventBridge

## Monitoring with Amazon CloudWatch

AWS Lambda integrates directly with **Amazon CloudWatch** for monitoring and troubleshooting.

CloudWatch provides visibility into:

* Function invocations
* Execution duration
* Errors
* Logs
* Performance metrics

Lambda memory allocation can be configured up to **10 GB**.

Increasing memory also provides additional CPU and network performance, allowing functions to process workloads more efficiently.

## Supported Languages and Runtimes

AWS Lambda supports a wide range of programming languages.

Common supported runtimes include:

* Python
* Node.js
* Java
* C#
* .NET
* PowerShell
* Ruby

Lambda also supports **custom runtimes**, allowing developers to run languages that are not officially supported by implementing the Lambda Runtime API.

This flexibility enables developers to build serverless applications using the language and tooling they are most familiar with.

---

## Container Image Support

Applications can also be packaged as **container images** instead of ZIP deployments.

This is useful when applications require:

* Custom dependencies
* Large libraries
* Specific runtime environments
* Greater deployment flexibility

Lambda supports container images that implement the Lambda Runtime API.

For more general-purpose container workloads, services such as **Amazon ECS** or **AWS Fargate** are often more appropriate.

## Common Use Cases

AWS Lambda is commonly used for:

* File processing
* Event-driven automation
* API backends
* Image resizing
* Data processing
* Scheduled jobs
* Serverless web applications

Lambda is particularly effective when applications need to react automatically to events generated by other AWS services.

---

## Key Takeaways

* Lambda charges only for requests and execution time
* AWS Free Tier includes 1 million monthly requests
* Lambda integrates seamlessly with many AWS services
* CloudWatch provides monitoring, logging, and performance metrics
* Memory allocation also affects CPU and network performance
* Lambda supports multiple programming languages
* Custom runtimes allow additional language support
* Applications can be deployed using container images
* Lambda is ideal for event-driven and serverless workloads
* ECS or Fargate may be better suited for long-running container applications
